### 무엇을 해결하나요?

개인 투자자는 가격 흐름, AI 모델 전망, 증권사 리포트를 각각 확인하더라도 **정보를 어떤 기준으로 결합했고, 그 결과 종목 순위와 투자 비중이 왜 달라졌는지** 파악하기 어렵습니다. 이 MVP는 세 정보원을 하나의 포트폴리오 계산 과정에 연결하고 **리포트 반영 전후 결과와 근거**를 비교하도록 돕습니다.

- **MOM:** 최근 20거래일 수익률에 따른 모멘텀 순위
- **PAIR:** 동결된 확산모델에서 동일 초기 노이즈를 사용한 Full−Macro 생성 결과의 차이로 만든 순위
- **REPORT:** 증권사 리포트 목표주가와 당시 종가의 괴리율을 이용한 상대 순위

현재는 다음과 같이 **순위 점수**를 결합합니다.

```text
기본 점수 = (1 − PAIR 비율) × MOM + PAIR 비율 × PAIR
최종 점수 = (1 − REPORT 비율) × 기본 점수 + REPORT 비율 × REPORT
                  ↓
           위험 기반 최적화
                  ↓
        종목별 목표 투자 비중
```

**주의:** 결합 비율은 예상 수익률이나 최종 투자 비중을 그대로 평균하는 값이 아닙니다. 최종 비중은 O 생성 경로 공분산을 이용하는 기존 BL/CVaR 기반 최적화에서 계산합니다. 기본 **PAIR 50%·REPORT 50%**는 MOM 25%·PAIR 25%·REPORT 50%의 순위 점수 결합에 해당합니다.

### 현재 MVP에서 체험할 수 있는 기능

| 화면 탭 | 기능 |
| --- | --- |
| **① 기간 백테스트** | MOM+PAIR 대비 REPORT 반영 전략의 수익곡선, Sharpe, MDD, 변동성·비중 변화 비교 |
| **② 특정 매수일 포트폴리오** | 과거 KRX 매수일을 선택해 종목 순위·비중·리포트 근거·20거래일 생성 시나리오 확인 |
| **③ 리포트 신규 수집 (선택)** | 새 증권사 PDF 수집, Claude/Codex를 이용한 구조화·검증·컨센서스 갱신 |

②에서 **로컬 해설**은 별도 AI 계정 없이 이용할 수 있습니다. Claude/Codex를 연결하면 선택적으로 **AI 설명 생성 및 별도 의미 검증**도 체험할 수 있습니다. 실제 주문이나 자동매매는 지원하지 않습니다.

## 2. 설치 및 접속

**지원 환경:** Windows 11 64비트 권장 / macOS(Apple Silicon·Intel) 설치 스크립트 제공. Python 3.11 가상환경과 CPU로 실행하며 **GPU·Jupyter·Node.js는 기본 웹 실행에 필요하지 않습니다.** 최초 설치 및 외부 시세 수집에는 인터넷 연결이 필요합니다. macOS는 설치 절차를 제공하지만 전체 백테스트의 실기기 검증은 별도 확인이 필요합니다.

### Windows 11

**최초 1회 설치:** PowerShell에서 실행합니다. 필요한 Git·Python 3.11 확인/설치, 저장소 복제, 웹 의존성 설정 및 실행을 진행합니다.

```powershell
$bootstrap = Join-Path $env:TEMP 'AI-Capstone-bootstrap.ps1'
Invoke-WebRequest 'https://raw.githubusercontent.com/whd8070/AI-Capstone/main/bootstrap_windows.ps1' -OutFile $bootstrap
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $bootstrap
```

**설치 완료 후 다시 실행:**

```powershell
cd "$HOME\AI-Capstone"
.\run_windows.cmd
```

### macOS

**최초 1회 설치:** 터미널에서 실행합니다.

```bash
curl -fL https://raw.githubusercontent.com/whd8070/AI-Capstone/main/bootstrap_mac.sh -o /tmp/ai-capstone-bootstrap-mac.sh
bash /tmp/ai-capstone-bootstrap-mac.sh
```

Git 명령줄 도구 설치 창이 표시되면 설치를 완료한 후 같은 명령을 다시 실행합니다. Homebrew 설치는 필요 시 승인을 요청합니다.

**설치 완료 후 다시 실행:**

```bash
cd "$HOME/AI-Capstone"
bash ./run_mac.sh
```

**공통:** 기본 설치 폴더는 사용자 홈의 `AI-Capstone`입니다. 다른 폴더에 복제했다면 해당 저장소 루트로 이동하세요. 실행 후 브라우저에서 **http://127.0.0.1:8501**을 열고 종료 시 터미널에서 `Ctrl+C`를 누릅니다. 이후 실행에 매번 재설치는 필요하지 않습니다.

**업데이트:** 서버 종료 → 저장소 루트에서 `git pull origin main` → 운영체제별 재실행. 의존성 재설정이 필요한 경우에만 Windows의 `start_windows.cmd` 또는 macOS의 `bash ./start_mac.sh`를 사용합니다.

## 3. 핵심 기능 체험 순서

**체험 역할:** 증권사 리포트 반영 전후로 보유할 종목과 투자 비중이 어떻게 달라지는지 확인하려는 개인 투자자.

**체험 목표:** 미리 제공된 리포트 데이터를 사용해 포트폴리오를 만들고, 같은 기준의 백테스트를 확인한 뒤, 원하는 경우 신규 리포트와 AI 설명을 추가합니다.

**권장 경로:** **② 포트폴리오 → ① 백테스트**부터 체험하세요. **③은 선택 기능**이며 신규 리포트 반영이나 Claude/Codex 설명이 필요한 경우에만 먼저 설정하면 됩니다.

### 사용 전 꼭 확인할 사항

| 상황 | 주의할 점과 권장 행동 |
| --- | --- |
| **기존 시나리오·특징 캐시가 준비된 날짜** | 기존 테스트 환경에서는 ② 포트폴리오 생성에 **약 3분**이 걸렸습니다. 이는 관찰된 예시일 뿐, PC 성능·시세 확인·캐시 상태에 따라 달라지며 **3분 이내 완료를 보장하지 않습니다.** |
| **캐시가 없거나 준비된 범위 밖의 날짜** | 필요한 시세 다운로드, 특징 계산 및 CPU 확산모델 시나리오 생성이 추가돼 **훨씬 오래 걸릴 수 있습니다.** 날짜가 기본 리포트 제공 범위에 있다는 사실과 **모델 시나리오 캐시가 존재한다는 사실은 별개**입니다. 처음에는 아래 예시 날짜로 테스트하고, 계산 화면의 단계별 진행·오류를 확인하세요. |
| **②에서 기본 제공 이후의 매수일 선택** | ③에서 새 PDF를 다운로드·구조화·검증하여 **컨센서스 반영까지 완료하지 않았다면 신규 리포트는 사용되지 않습니다.** 대신 해당 매수일 이전에 저장된 **유효한 과거 보고서(최대 90일 이내)**가 있으면 그 정보는 사용될 수 있습니다. 과거 자료도 부족하면 REPORT가 활성화된 계산은 오류로 중단될 수 있습니다. **새 리포트가 자동 수집됐다고 가정하지 마세요.** |
| **③에서 'PDF만 다운로드' 선택** | 원본만 저장되고 REPORT 점수는 **갱신되지 않습니다.** 최신 리포트 반영이 목적이라면 **'PDF 다운로드 + 선택한 LLM 구조화 + 컨센서스 반영'**을 끝까지 완료한 뒤 ②에서 **포트폴리오를 다시 생성**해야 합니다. 구조화 대기·실패 건은 새 컨센서스에 반영되지 않습니다. |
| **②의 매수일 또는 왼쪽 결합 비율 변경** | 기존 화면의 수치가 새로운 설정에 자동 재계산된 결과라고 생각하지 마세요. **'포트폴리오 생성 (수치 먼저 표시)'을 다시 눌러** 날짜·비율과 결과가 일치하는지 확인하세요. AI 설명도 새 수치 생성 후 호출합니다. |
| **①에서 기간을 길게 선택** | 여러 거래일의 신호를 계산하므로 **단일 매수일 생성보다 오래 걸릴 수 있습니다.** 첫 점검은 '처음 5개 신호만 점검'을 사용하고, 이후 정식 백테스트로 진행하세요. |
| **CLI 로그인·AI 설명 이용** | Claude/Codex는 설치·로그인·이용 가능 사용량이 필요합니다. **로컬 설명만 사용할 때는 불필요**하며, AI 설명·검증 시간이 별도로 발생합니다. AI 해설 실패는 투자 비중 계산 실패와 구분됩니다. |

> **데이터 시점 확인:** 화면 상단의 **현재 컨센서스 파일 날짜 범위**, ② 실행 결과의 **유효 리포트 종목 수**, ③의 **구조화 대기·완료 상태**를 확인하세요. 매수일 **당일 또는 이후** 발행된 리포트는 사용하지 않습니다. **리포트가 없는 종목은 다른 유효 종목들의 중앙값으로 중립 처리**하며, 정보가 없다는 사실 자체를 긍정적·부정적 전망으로 해석하지 않습니다.


### 체험 A. ② 특정 매수일 포트폴리오 — 가장 먼저 실행

1. 왼쪽 메뉴에서 **PAIR 비율 0.50**, **REPORT 비율 0.50**을 설정합니다.
2. 상단 **「특정 매수일 포트폴리오」** 탭을 선택합니다.
3. **매수일 2026-11-05**를 선택합니다. 예시 날짜는 기본 리포트의 마지막 날짜인 2026-11-04 이후의 실제 거래일입니다.
4. **포트폴리오 설명 방식 → 「데이터 기반 로컬 해설 (LLM 호출 없음)」**을 선택합니다.
5. **「포트폴리오 생성 (수치 먼저 표시)」** 버튼을 누릅니다.
6. REPORT 적용 전후 **종목 순위·목표 비중**, 실제 편입 종목, 투자비중 변화 근거, **동결 모델 O 생성 시나리오**를 확인합니다.
7. **「실제 편입 종목만 보기」**를 해제하면 0% 비중 종목을 포함한 전체 44종목이 표시됩니다. **「최종·기존 포트폴리오 CSV」**, **「설명 TXT」**로 결과를 저장할 수 있습니다.

표시되는 목표 비중은 **해당 매수일에 새로 편입하는 1개 슬리브 내부의 비중**이며, 기존 나머지 슬리브를 포함한 전체 계좌 비중은 아닙니다. 모델 추론은 **K=128, 시드=0**으로 고정되어 있습니다. **기존 캐시가 준비된 날짜는 약 3분이 걸렸지만, 캐시 밖 날짜는 신규 추론 등으로 훨씬 오래 걸릴 수 있습니다.** 실제 시간은 실행 환경에 따라 달라집니다.

### 체험 B. ① 기간 백테스트 — 성과 비교

1. 상단 **「기간 백테스트」** 탭을 선택합니다.
2. 예시: **시작 신호일 2026-10-27**, **종료 평가일 2026-11-04**, PAIR 0.50, REPORT 0.50.
3. 처음 작동을 확인하려면 **「처음 5개 신호만 점검 (정식 백테스트 아님)」**을 선택합니다.
4. **「백테스트 실행 (별도 프로세스)」**를 누르고 **「이전/진행 중인 작업」**에서 처리 상태를 확인합니다.
5. **계산 완료** 표시 후 REPORT 적용 전후 **NAV 그래프, 누적 수익률, Sharpe, MDD, 연환산 수익률·변동성, 거래비용**과 **날짜별 순위·비중 CSV**를 확인합니다.
6. 실제 기간 성과를 비교하려면 **5개 신호 점검을 해제**하고 충분한 기간을 지정해 다시 실행합니다.

이 백테스트는 **신호일 종가 기준 계산 → 다음 KRX 거래일 시가 체결**, **20개 슬리브 순환** 방식입니다. 5개 신호 점검 결과는 정식 백테스트 성과가 아닙니다.

### 체험 C. ③ AI 연결과 포트폴리오 설명 — 선택

**기존 리포트만 사용할 경우 새 PDF 수집은 필요하지 않습니다.** Claude/Codex 설명을 원할 때에만 다음을 수행합니다.

1. **「리포트 신규 수집 (선택)」** 탭 → **「AI 모델 연결하기」**에서 Codex/Claude의 연결 상태를 확인합니다.
2. Windows 로컬 환경에서는 필요 시 **「설치 창 열기」 → 「로그인 창 열기」 → 「연결 상태 다시 확인」** 순으로 진행합니다. macOS에서는 화면에 있는 터미널 설치·로그인 안내를 사용합니다.
3. **「연결 완료 · 사용 가능」** 상태가 확인되면 ② 탭에서 **포트폴리오 설명 방식**으로 연결된 Claude 또는 Codex를 선택합니다.
4. 먼저 **「포트폴리오 생성 (수치 먼저 표시)」**를 실행하고, 이어서 **「AI 설명 생성·독립 검증 (모델 추론 재실행 없음)」**을 누릅니다.
5. 선정 이유·리포트 근거·비중 결정·위험관리·불확실성의 **5개 항목**과 검증 상태를 확인합니다.

AI 설명이 독립 검증에 실패하거나 호출 오류가 발생하면 **로컬 해설로 대체**됩니다. `PASS`는 해당 설명에 대한 독립 검증 상태이며, 로컬 해설의 `LOCAL_RULE_ONLY`는 독립 의미 검증 통과를 의미하지 않습니다. **AI는 포트폴리오 수치나 비중을 수정하지 않습니다.**

### 체험 D. ③ 신규 리포트 반영 — 선택

기본 데이터에는 이미 구조화한 보고서가 포함되어 있습니다. **2026-11-04 이후 발행된 새 보고서를 투자 신호에 반영**하려는 경우에만 실행합니다. **②를 먼저 실행해도 새 보고서는 자동 수집되지 않습니다.** 해당 날짜에 유효한 과거 보고서가 있으면 그 정보만 반영되며, 신규 보고서를 쓰려면 아래 구조화·컨센서스 갱신을 완료해야 합니다.

1. ③ 탭에서 **연결된 Claude/Codex CLI**를 확인하고 **신규 리포트를 구조화할 LLM**을 선택합니다.
2. **리포트 수집 마감일**을 기본 데이터 마지막 날짜(2026-11-04)보다 뒤로 지정합니다. 예: **2026-11-10**.
3. **「PDF 다운로드 + 선택한 LLM 구조화 + 컨센서스 반영」**을 선택합니다. **「PDF만 다운로드」는 포트폴리오 신호를 갱신하지 않습니다.**
4. 구조화 최대 건수·사용량 조건을 확인하고 **「수집 범위·선택한 CLI 사용량·시점 제한을 확인했습니다」**를 체크합니다.
5. **「선택한 단계 실행」**을 누르고 완료·실패·구조화 대기 상태를 확인합니다.
6. 정상 구조화·검증과 컨센서스 갱신을 마친 후 **② 탭으로 돌아가** 새 매수일을 선택해 포트폴리오를 생성합니다.

**실행 불가 사유가 표시되면** 새 수집 구간 유무, CLI 연결, 실행 확인 체크를 확인하세요. ③에서 **「구조화 완료 후 해당 매수일 포트폴리오까지 계산」**을 선택했다면 매수일은 수집 마감일보다 늦어야 합니다. 수집·구조화가 미완료된 자료는 반영하지 않으며 완료된 캐시는 재사용합니다. Claude/Codex 사용은 계정 권한·사용량 정책의 영향을 받습니다.

## 4. 기대 결과 및 다시 실행하는 방법

## 5. 계정·사전 준비·제한 및 오류 대응

| 항목 | 안내 |
| --- | --- |
| **계정** | 기본 포트폴리오·백테스트·로컬 해설에는 별도 계정이 필요하지 않습니다. AI 설명·신규 PDF 구조화에는 **Claude/Codex CLI 설치 및 본인 로그인**이 필요합니다. 웹이 비밀번호·토큰을 직접 입력받지 않습니다. |
| **샘플 데이터** | `main` 브랜치의 종목 목록 `src/diffusion/data/kr/metadata/stable_kospi200_44.csv`, 모델 `src/diffusion/checkpoints/kr/stable_best.pt`, 리포트 데이터 `agents/collection/data/handoff/`. 기본 컨센서스 수록 범위는 **2025-11-04~2026-11-04**입니다. |
| **외부 데이터** | 실행 시 시세 등 외부 자료를 내려받을 수 있습니다. 인터넷/데이터 제공처 문제로 계산이 실패할 수 있고, 누락 가격을 임의로 만들어 사용하지 않습니다. |
| **리포트 시점** | 매수일 당일·이후의 리포트는 사용하지 않습니다. REPORT 유효 종목이 부족하면 계산이 중단될 수 있습니다. |
| **연구용 한계** | 고정 44종목의 생존편향 가능성, 리포트 목표가의 기간과 모델의 20거래일 기간 차이, 슬리피지·세금·거래정지의 미반영이 있습니다. 수익 보장·투자 자문·실거래 기능은 제공하지 않습니다. |

**문제가 생기면:** `8501` 접속이 안 될 때는 실행 터미널과 포트 점유 여부를 확인합니다. `ModuleNotFoundError` 등 패키지 문제는 Windows `start_windows.cmd`, macOS `bash ./start_mac.sh`로 설치 상태를 점검합니다. 모델 파일 누락 시 `stable_best.pt`가 실제 파일로 존재하는지 확인하세요. Claude/Codex가 선택되지 않으면 ③ 탭에서 CLI 로그인 상태를 다시 확인합니다. 신규 리포트의 **「선택한 단계 실행」**이 진행되지 않으면 화면의 **실행 전 확인할 사항**을 먼저 해결하세요.

## 6. 추후 보완할 부분 — SPEC v3.1 (아직 미구현)

현재 MVP는 **MOM·PAIR·REPORT의 선형 순위 점수 결합**만 지원합니다. 향후에는 사용자가 각 정보의 사용 여부와 결합 원칙을 선택할 수 있도록 확장합니다.

| 우선순위 | 보완 기능 | 사용자에게 제공할 변화 |
| --- | --- | --- |
| **1단계 — 신호 선택·결합** | MOM/PAIR/REPORT 개별 활성화, 선형 가중 결합(**LINEAR**), 정보 불일치 패널티(**CONSENSUS**), 주력 신호의 조건부 확인(**CONFIRMATION**) | 단순 비율 조절을 넘어 정보 충돌을 처리하는 방식 선택 |
| **2단계 — 리포트 조건·비교** | 리포트 경과일/최소 증권사 수 필터, 기본 전략 대비 사용자 전략 비교, 변경된 조건의 설명·검증 | 어떤 자료가 실제로 적용됐고 순위·비중이 왜 달라졌는지 확인 |
| **3단계 — 포트폴리오 제약** | 개별 종목·섹터 상한, 편입 제외, 전체 슬리브 노출 검사 등 | 선택한 위험 조건을 최적화에 반영(실현 불능 시 오류 표시) |

**중요:** 위 기능은 현재 웹에서 동작하지 않는 **개발 예정 요구사항**입니다. 구현 후에도 기존 기본 전략과의 호환성, 동일 조건 재현성, 리포트 시점 제약, 설명의 사실 검증을 유지해야 합니다. 자세한 기능·수용 기준은 [SPEC v3.1의 11절](SPEC.md#11-사용자-선택형-결합-및-전략-비교-v31)을 참고하세요.
