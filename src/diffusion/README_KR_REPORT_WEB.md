# 한국 주식 MOM + PAIR + REPORT 로컬 웹

이 폴더의 기존 `kr_pair_cpu.py`, `kr_pair_core.py`, `KR_MOM_PAIR_20_SLEEVES_CPU.ipynb`에 REPORT 순위 신호를 추가한 **로컬 Streamlit 실험용 대시보드**입니다. 자동 주문 기능은 없습니다.

> 처음 복제했다면 저장소 [루트 README](../../README.md)의 빠른 시작을 따라 주세요. Windows에서는 PowerShell의 실행 정책 문제를 피하는 `start_windows.cmd`를 사용합니다.

## 1. 설치 및 실행 (웹만)

Windows 11 또는 macOS, Python 3.11(64비트), Git과 인터넷 연결을 준비합니다. Jupyter와 Node.js는 기본 웹에 필요하지 않습니다.

**Windows 11 (새 PC, PowerShell 또는 CMD):**

```powershell
git clone https://github.com/whd8070/AI-Capstone.git
cd AI-Capstone
.\start_windows.cmd
```

먼저 [Git for Windows](https://git-scm.com/downloads/win), [Python 3.11 64비트](https://www.python.org/downloads/)를 설치하고 새 터미널을 여세요. Python 3.12/3.13만 있는 PC에서는 3.11도 설치해야 합니다. `start_windows.cmd`는 저장소 루트에 있으며 파일 탐색기에서 더블클릭할 수도 있습니다. 설치 스크립트는 `py -3.11`, `python`, `python3` 순서로 실제 Python 3.11(64비트) 여부를 확인합니다.

이 실행기는 `src/diffusion`에서 가상환경을 준비하고 pip 설치, `pip check`, 핵심 모듈 import 검사를 수행한 다음 Streamlit을 실행합니다. `.venv`가 있으면 재사용하며 다른 버전의 환경은 무단 삭제하지 않습니다. PowerShell 정책 제한은 실행 프로세스에만 적용되는 `-ExecutionPolicy Bypass`로 회피하며 전역 정책을 수정하지 않습니다.

**Windows 초기 설치 문제 해결:**

- `git` 명령을 찾지 못함: Git 설치 후 새 터미널에서 다시 실행
- Python 3.11이 없음: Python 3.11 64비트를 설치하고 새 터미널에서 `py -3.11 --version` 확인
- `running scripts is disabled`: `.ps1` 직접 실행 대신 저장소 루트의 `.\start_windows.cmd` 실행
- 기존 `.venv` 버전이 다름: 해당 환경을 백업하거나 이름을 바꾼 뒤 다시 실행
- PyTorch DLL/import 오류: [Microsoft Visual C++ Redistributable x64](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist) 설치 여부 확인 후 재시도
- pip 다운로드 실패: 네트워크, 프록시, 디스크 공간을 확인하고 다시 실행. 데이터/캐시는 삭제하지 않음
- 체크포인트 또는 리포트 파일 없음: clone이 완전한지 확인. `checkpoints/kr/stable_best.pt`가 Git LFS 포인터가 아닌 실제 모델 파일인지 확인
- 포트폴리오 계산 실패: 최초 실행의 44종목 Yahoo/FRED 수집, 선택한 KRX 거래일, 데이터 제공자 연결 상황 확인. 설치 완료와 데이터 수집 성공은 별개

기존 `.ps1` 파일은 고급 사용자를 위해 유지합니다. 기본적으로는 루트의 Windows 실행기를 사용하세요.

**macOS 터미널 —** 저장소를 복제한 후 `src/diffusion`에서 (Python 3.11이 없다면 Homebrew로 `brew install python@3.11`):

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements_kr_report_web.txt
python -m streamlit run kr_report_web.py --server.address 127.0.0.1 --server.port 8501
```

브라우저에서 **http://127.0.0.1:8501**로 접속합니다. 종료는 `Ctrl+C`입니다. 웹만 사용한다면 `JupyterLab`, `ipykernel`, `nbformat`, `matplotlib`을 설치하지 않습니다. 신규 리포트 다운로드·추출 화면은 Python의 `requests`·`pymupdf`를 사용하며, **Claude/Codex 설명·추출을 선택할 때만** 선택한 CLI가 필요합니다. 기존 Diffusion 노트북은 선택 사항이므로 해당 [별도 안내](README_KR_PAIR_CPU.md)를 따르세요.

## 2. 두 가지 핵심 기능

**백테스트:** REPORT 데이터가 있는 기간에서 시작·종료일, PAIR 비율 `p`, REPORT 비율 `r`을 선택합니다. 매 거래일 **종가 신호 → 다음 거래일 시가에 신규 슬리브 1개**를 체결하며 총 **20슬리브를 순환**합니다. REPORT 적용 전·후 NAV 그래프, Sharpe, MDD, 연환산 수익률/변동성, 거래비용, 일별 비중·순위 CSV를 보여 줍니다. 계산은 별도 프로세스에서 실행되며 웹을 닫아도 작업 프로세스는 지속될 수 있습니다.

**특정 매수일 포트폴리오:** 날짜를 **매수일**로 입력하면 직전 KRX 거래일 종가까지 확인된 시세를 확보하고 확산모델을 실행해 해당 매수일 **신규 1개 슬리브의 목표 비중**을 계산합니다. REPORT 적용 전·후 종목별 비중·순위 차이, 목표가 괴리율, 근거/리스크, 20거래일 생성 시나리오를 제공합니다. 전체 20슬리브 계좌의 현재 보유 비중과는 다릅니다.

웹에서 변경 가능한 비율은 다음과 같습니다.

```text
base  = (1 - p) × rank_z(MOM 20일) + p × rank_z(PAIR F−M)
final = (1 - r) × base + r × rank_z(REPORT 목표가 괴리율)
```

이는 **최종 투자비중을 단순 평균하는 방식이 아니라**, 순위 신호를 결합하고 기존 O 경로 공분산 및 BL/CVaR 위험 최적화에 입력하는 방식입니다. **웹의 K=128, 시드=0은 고정**입니다.

## 3. 정보 시점과 데이터

- REPORT: `daily_consensus.csv`의 종목별 최신 `tp_median`과 **신호일 비수정 종가**로 `(목표가/종가) - 1`을 산출해 횡단면 순위화합니다. **매수일 당일 리포트는 제외**하고, 최장 90일 이전의 최신 유효 리포트만 사용합니다.
- 리포트 없는 종목은 유효 종목들의 중앙값으로 중립 처리합니다. 유효 REPORT 종목이 두 개 미만이면 REPORT 비율이 0보다 큰 계산을 중단합니다.
- 리포트 파일의 기본 수록 기간은 **2025-11-04 ~ 2026-11-04**입니다. 신규 리포트 수집은 **선택** 기능이며, 네이버 PDF 다운로드 후 로그인된 `codex` 또는 `claude` CLI를 통한 구조화가 별도로 필요할 수 있습니다. 과거에 없던 보고서를 임의 생성하지 않습니다.
- 최신 날짜 시장 데이터는 `yfinance` 및 FRED에서 수집합니다. 수정 종가(모델/평가)와 비수정 종가(목표가 괴리율), 조정 시가(체결)를 구분합니다.
- 보고서 발행 시각이 없는 한계 때문에, 당일 보고서를 사용하지 않는 보수적인 정렬을 적용합니다.

### 페이지별 실행 순서와 선행 준비

| 상황 | 권장 순서 | Claude/Codex 로그인 | 신규 PDF 구조화 |
| --- | --- | --- | --- |
| 기존 보고서를 사용하고 로컬 해설만 필요 | **2페이지** → '데이터 기반 로컬 해설' → 포트폴리오 생성 | 불필요 | 불필요 |
| 기존 보고서로 AI 설명을 생성 | **3페이지**에서 CLI 연결 상태 확인 → **2페이지**에서 로그인된 Claude/Codex 선택 → 생성 | 설명용 CLI 로그인 필요 | 불필요 |
| 기존 보고서 수록 기간을 넘어선 신규 보고서를 투자 신호에 반영 | **3페이지**에서 CLI 연결·모델 선택 → PDF 수집 **+ 구조화 + 컨센서스 반영** 완료 → **2페이지**에서 포트폴리오 생성 | 추출용 CLI 로그인 필요 | 필요 |

**먼저 구분할 것:** 포트폴리오 설명 에이전트와 리포트 구조화 에이전트는 서로 다른 기능입니다. **AI 설명을 선택했다고 반드시 새 PDF를 수집·구조화해야 하는 것은 아닙니다.** 기존에 구조화된 REPORT 데이터가 충분하면 CLI 인증 상태만 확인하고 2페이지에서 바로 해설을 생성할 수 있습니다. 반대로 날짜에 필요한 최신 보고서를 반영하려면 먼저 3페이지에서 구조화와 컨센서스 갱신을 마쳐야 합니다. LLM 연결 여부와 별개로 모델 체크포인트와 시세 데이터는 필요합니다.

**PDF만 다운로드 ≠ REPORT 갱신:** 3페이지의 'PDF만 다운로드'는 원문 PDF·메타데이터를 캐시에 저장할 뿐, 목표가·근거·위험을 추출하거나 포트폴리오에 반영하지 않습니다. 신규 자료를 실제로 사용하려면 **'PDF 다운로드 + 선택한 LLM 구조화 + 컨센서스 반영'**을 실행하세요. 화면에서 '구조화 대기'가 남은 경우에는 추출 상한/사용량·오류를 확인해 재실행해야 하며, 미완료 구간의 컨센서스는 게시하지 않습니다. 재실행 시 수집한 PDF 및 정상 추출 기록은 재사용합니다.

**오류를 피하는 점검 순서:** 3페이지에서 사용하려는 CLI가 '로그인 확인 · 사용 가능'인지 확인하고, 필요한 경우 구조화가 완료되어 컨센서스 파일이 갱신되었는지 확인합니다. 이후 2페이지에서 **실제 KRX 매수 거래일**과 설명 모델을 선택합니다. 선택한 날짜에 유효한 REPORT 종목이 충분하지 않으면 REPORT 비율을 낮추거나 데이터를 먼저 수집해야 합니다. 매수일 당일·미래 리포트는 사용하지 않습니다. LLM이 실행 중 실패하면 계산 결과는 유지하고 로컬 설명으로 전환하며, 실패 경고를 표시합니다.

### 2번째·3번째 페이지의 LLM 선택 및 상대 순위 해설

**2번째 페이지(특정 매수일 포트폴리오)**에서 기본 로컬 해설, 로그인된 Claude CLI, 로그인된 Codex CLI를 선택합니다. 모델 계산 후 횡단면 랭크 근거를 제공하되, AI 해설이 숫자·종목별 목표 비중을 고치지 않도록 합니다. LLM 로그인·실행이 실패하면 로컬 해설로 복귀하고 실패 사실을 명시합니다.

**3번째 페이지(리포트 신규 수집)**에서는 PDF만 다운로드하거나 **로그인된 Claude/Codex CLI** 중 하나로 PDF를 구조화합니다. 목표주가·근거·리스크의 JSON 스키마 및 원문 인용을 검증하고 모든 수집 건을 완료했을 때에만 로컬 컨센서스에 추가합니다. 구조화 후 포트폴리오 생성 옵션을 활성화하면 **별도의 설명 CLI**(로컬/Claude/Codex)를 선택할 수 있습니다.

**해설 구조:** ① 기존 MOM·PAIR 기준 횡단면 점수 ② REPORT 반영 점수 및 상대적인 순위 위치 ③ 상대 점수가 역전된 경쟁 종목(종목 코드 및 변화량) ④ 비중은 공분산·BL/CVaR 공동 최적화 결과라는 제약 ⑤ 리포트 장점과 반대 위험 및 시나리오 해석 순서입니다. 개별 기업의 리포트 내용은 위험과 투자 맥락을 보여주지만 **순위 변화의 단일 인과 원인이라는 뜻이 아닙니다.** 리포트가 없는 종목도 타 종목과의 상대 비교 때문에 순위가 달라질 수 있습니다. 해당 매수일보다 늦게 나온 리포트는 사용하지 않습니다.

**선택적 CLI 설치:** Codex는 `npm install -g @openai/codex`, `codex login`, `codex login status`. Claude는 Windows `.\\setup_claude_windows.ps1` 또는 macOS `bash ./setup_claude_mac.sh` 실행 후 `claude auth login`, `claude auth status`. VS Code 확장 인증이 독립 실행 CLI에 자동으로 공유되지는 않을 수 있습니다. 기존 REPORT/PAIR 웹을 실행할 때 CLI는 필수가 아닙니다.

**계산 한계:** PDF 추출 후에도 원본 보고서 내용과 실제 가격을 독립 검증해야 합니다. 설명은 주어진 데이터에 대한 해석이며 재현 가능한 인과추정이나 실현수익률 예측이 아닙니다. CLI 토큰/환산비용 중단 장치는 전체 사용자 청구액을 제한하지 않습니다.

### 결과 표시 속도 개선

2페이지는 **포트폴리오 생성 (수치 먼저 표시)** 로 먼저 수치 비중, 근거와 로컬 해설을 반환합니다. 그 뒤에만 **AI 설명 생성·독립 검증 (모델 추론 재실행 없음)** 버튼으로 별도의 Claude/Codex 생성·검증을 호출합니다. 같은 계산 결과를 재사용하므로 AI 문장을 고치기 위해 STABLE 시나리오·BL/CVaR을 다시 계산할 필요가 없습니다. 수치 결과와 AI 설명은 서로 다른 단계입니다.

처음 포트폴리오 생성은 로컬 시장 시세, 피처 구성, 동결 STABLE 128개 시나리오, 위험 최적화 때문에 여전히 시간이 걸릴 수 있습니다. 모델 시나리오 캐시를 재사용하면 시간이 감소할 수 있지만, 최초 다운로드 및 캐시가 없을 때의 수행 시간은 환경마다 다릅니다. 설명 에이전트의 시간은 CLI 연결·문단 길이·검증 재생성 횟수에 따라 달라지며 실측 전에는 일정 시간을 보장하지 않습니다. 신규 수집 탭의 원클릭 수집 + 포트폴리오는 일괄 호출 방식으로, 설명 단계가 끝나기 전 결과가 늦게 보일 수 있습니다.

### 포트폴리오 설명·독립 검증 (MVP 추가)

- **2·3페이지 포트폴리오 표:** 기본으로 최종 비중이 양수인 실제 편입 종목만 표시합니다. 체크를 해제하면 44종목 전체를 표시합니다. 비중은 %, 변화는 %p로 소수점 둘째 자리까지 표시하지만 원본 CSV 정밀도는 유지합니다.
- **설명 에이전트:** 실제 편입 종목을 누락 없이 다섯 가지 영역(선정 이유, 리포트 근거, 비중 결정, 위험관리, 불확실성)으로 서술합니다. 순위·비중·시나리오는 사전 포맷된 수치를 쓰고, 제공된 리포트 근거 밖의 기업 사실이나 인과는 만들지 않습니다.
- **검증 에이전트:** 선택한 CLI로 설명 생성 후 별도 호출하여 모든 설명 문단을 근거 팩트와 대조합니다. 필수 섹션·숫자 정밀도·주장 판정·근거 ID를 규칙으로도 검사합니다. 전체 검증이 승인된 때만 PASS로 표시하고, 최초 생성 이후 최대 2회 재생성·전면 재검증합니다.
- **실패 처리:** 거절·미판정·호출 실패 시 LLM 설명을 사용하지 않고 로컬 설명으로 대체합니다. 로컬은 LOCAL_RULE_ONLY로 표시하며 독립 의미 검증을 통과했다고 주장하지 않습니다. 검증 이력은 verification.json에 저장합니다.
- **리포트 부재:** 종목별 중앙값 중립 처리와 부재를 설명합니다. 유효 리포트가 2개 미만이거나 횡단면 점수 구별이 안 되면 REPORT>0 계산은 중단합니다.
- **검증 범위:** 이번 단계는 MVP용 주장 검증의 초기 연결입니다. SPEC의 P30/M30/G30 성능 합격, 내용 해시로 잠긴 게시 게이트 전 과정, 실제 금융 사실의 독립 보증은 완료된 것으로 간주하지 않습니다.

오프라인 회귀 테스트: src/diffusion에서 다음을 실행합니다.

```powershell
python -m unittest test_kr_report_engine test_kr_report_status test_kr_report_verification -v
```

실제 Claude/Codex 의미 검증은 로그인된 CLI에서 별도로 E2E 확인해야 합니다.

## 5. 테스트·문제 해결

Windows PowerShell:

```powershell
cd src\diffusion
.\.venv\Scripts\python.exe -m unittest test_kr_pair_cpu test_kr_report_engine test_kr_report_status -v
```

macOS 터미널 (`src/diffusion` 위치):

```bash
source .venv/bin/activate
python -m unittest test_kr_pair_cpu test_kr_report_engine test_kr_report_status -v
```

- `ModuleNotFoundError`: 설치에 사용한 `.venv\Scripts\python.exe`로 Streamlit을 실행했는지 확인하세요.
- `stable_best.pt` 없음: `checkpoints/kr/`에 **한국 모델 체크포인트**가 있는지 확인하세요.
- `WinError 5`: 구형 파일이 아닌 Git 최신 `kr_report_job.py`/`kr_report_jobs.py`를 사용하고, 기존 서버·백테스트 프로세스를 종료한 뒤 재실행하세요.
- 시세 다운로드 실패: Yahoo/FRED 연결 및 거래일 시세 제공 여부를 확인하세요. 결측치는 임의의 가격으로 대체하지 않습니다.
- `use_container_width` 경고: Streamlit API의 폐기 경고이며 기능 실패를 의미하지 않습니다.
- **Windows 수집 로그에서 `�` 글자가 보임:** 자식 Python 수집 프로세스의 CP949/UTF-8 출력 인코딩 불일치였습니다. 최신 `kr_report_collection.py`는 `PYTHONIOENCODING=utf-8` 및 `PYTHONUTF8=1`을 강제합니다. 기존 깨진 화면 출력은 복원되지 않으므로 새 코드를 받은 뒤 Streamlit을 재시작해 다음 수집부터 확인하세요. 이전에 받은 PDF/메타데이터 캐시는 유지됩니다.
- 선택적 설명 에이전트: 로컬 설명은 CLI 로그인이 필요하지 않습니다. Claude 또는 Codex로 설명/신규 PDF 구조화를 진행한다면 **선택한 CLI**의 설치·로그인 및 이용 가능 사용량을 확인해야 합니다.
