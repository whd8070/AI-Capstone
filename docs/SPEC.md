# SPEC v4.0 — 개미구조대 최종 MVP 제품·평가 계약

> 상태: **2026-11-17 최종 제출 기준 구현 범위 확정** · 정본: 이 문서
>
> 검증 구분: **구현 존재**, **자동 테스트 통과**, **실제 AI/E2E 실측**은 서로 다른 상태다. 이 문서는 기존 구현을 완성된 MVP의 기능 범위로 정의하며, 실행하지 않은 성능 평가를 통과했다고 주장하지 않는다. 근거: [최종 제출 안내](FINAL_SUBMISSION.md) 및 [Evals 설계](../evals/EVAL_DESIGN.md).

## 1. 문제와 최종 제품

금융 정보를 어떻게 결합할지 모르는 초보 투자자가 MOM(주가 흐름), PAIR(확산모델 기반 종목별 신호), REPORT(증권사 리포트 상대 순위)를 일일이 수학식으로 작성하지 않아도, **네 개 성향 선택과 선택적 추가 요청**으로 자신에게 맞는 **순위 신호 결합 수식**을 제안받고 적용할 수 있다. 수식은 실제 포트폴리오와 백테스트에서 사용하며, 종목별 결과와 근거를 확인한다.

**이용자:** 국내 주식의 투자 정보 결합 방식과 계산 근거를 비교하려는 개인/학생. 실제 주문·투자자문·수익 보장은 제공하지 않는다. 초기 설문은 소수 표본의 관찰이며 기능 효용이나 투자 성과가 검증됐다는 뜻이 아니다([문제 정의](PROBLEM.md), [온톨로지](ontology.yaml)).

**기능적 완료 정의:** 성향 → 에이전트 또는 규칙 기반 수식 제안 → 코드 검사·재시도 → 사용자 확정 → 포트폴리오/백테스트 재계산 → 로컬/선택적 AI 근거 설명·검증이 한 로컬 웹에서 연결된다. 현재 이 흐름을 MVP 최종 범위로 고정한다.

## 2. 최종 MVP 범위 — 웹 화면 4개

| 화면 | 구현되어 제공하는 기능 | 실행 근거 |
|---|---|---|
| ① 기간 백테스트 | 선택한 결합 수식에 따른 기본 MOM+PAIR 비교, REPORT 반영 전략 NAV·Sharpe·MDD·변동성·비중/순위 CSV, 5개 신호 빠른 점검 | `src/diffusion/kr_report_web.py`, `kr_report_engine.py`, `kr_pair_cpu.py` |
| ② 특정 매수일 포트폴리오 | 과거 KRX 매수일 기준 44종목의 신호, 새 슬리브 목표 비중·순위·리포트 근거·20거래일 시나리오. 로컬 해설 또는 AI 설명·독립 검증 | 동일 |
| ③ 리포트 신규 수집 (선택) | PDF 다운로드, Claude/Codex를 선택해 리포트 구조화·검증·컨센서스 갱신. PDF만 수집하면 신호는 갱신되지 않음 | `agents/collection/`, `kr_report_collection.py` |
| **④ 결합 수식 제안 (성향 조사)** | **초보 이용자를 위한 네 개 선택 질문·추가 메모 → Claude 에이전트가 수식/설명 제안 → 코드 검사·진단 및 최대 3회 재시도 → 규칙 기반 대체 → 사용자 수정·확정 → ①·② 계산에 적용** | `kr_formula_agent.py`, `kr_formula_survey.py`, `kr_formula_diag.py`, `kr_formula.py`, `kr_report_web.py` |

**제한:** ④의 Claude 에이전트 호출에는 로컬 Claude Code CLI 설치·로그인이 필요하다. 미연결 시 **규칙으로만 만들기 (LLM 없음)**를 사용할 수 있다. 제안 수식에 아직 성향 불일치가 있다면 경고를 표시하며, 수식 적용은 사용자 확정 후 이루어진다. 원본 프로그램은 실제로 구현된 이 동작을 따른다.

## 3. 모델·시점·수치 계약

- 한국 44종목의 고정 유니버스와 동결된 STABLE/PAIR 추론을 사용한다. 웹 기본 추론은 **20거래일 horizon, 20슬리브, K=128, seed=0**이다. 웹 실행의 수치 기준은 현재 구현을 따른다.
- 신호 **MOM**은 최근 20거래일 모멘텀 순위, **PAIR**는 동일 초기 노이즈 Full−Macro 생성 결과의 종목별 순위, **REPORT**는 당시 알고 있던 리포트 목표가/시점 종가의 괴리율 순위다.
- ②의 입력 날짜는 **매수일**이고 이용 가능한 신호는 직전 KRX 거래일까지다. 리포트 당일/미래 자료는 사용하지 않으며, 최대 90일 이내의 최신 유효 보고서를 참고한다. 리포트가 없는 종목은 중립 처리하되 결측을 숨기지 않는다. 유효 리포트 부족 시 REPORT를 반영하는 계산은 오류가 날 수 있다.
- 기본 결합식은 `0.5*(0.5*mom + 0.5*pair) + 0.5*report`, REPORT 반영 전 비교 기준은 `0.5*mom + 0.5*pair`이다. 결합식은 수익률을 직접 평균하거나 종목의 투자 비중을 직접 지정하는 식이 아니라 **순위 신호 값**을 생성한다.
- 실제 종목 비중은 기존 O 생성 경로 공분산과 BL/CVaR 기반 최적화 코드에서 결정한다. ②에서 보이는 비중은 **신규 1개 슬리브 내부 비중**이며 전체 20슬리브 계좌의 통합 보유 비중이라고 해석하면 안 된다.
- ①의 백테스트는 신호일 종가 정보를 기준으로 계산하고 다음 KRX 거래일 시가에 체결하는 가정을 사용한다. 빠른 5개 신호 점검은 정식 기간 백테스트 결과가 아니다.
- 리포트 목표가의 일반적인 중장기 전망을 **20거래일 실현 수익률 보장**으로 표현하지 않는다.

## 4. 수식 제안 에이전트의 실제 계약

### 4.1 입력

`kr_formula_survey.py`의 4개 문항:
1. 모멘텀 / MOM·PAIR 균형 / PAIR 중 선호
2. 증권사 리포트 신뢰도 낮음 / 보통 / 높음
3. 리포트 의견 항상 반영 / 뚜렷할 때만 반영
4. 신호 충돌 시 평균 / 보수적 선택 / 더 강한 신호 따름

추가 메모는 최대 300자, 비신뢰 사용자 참고 자료이며 프로그램 명령으로 실행되지 않는다. 질문만으로 수식을 모르더라도 이용할 수 있어야 한다.

### 4.2 출력·안전성

- Claude Code CLI에 성향·추가 메모·진단 결과를 전달해 `{"formula":"…","explanation":"…"}` 구조화 응답을 받는다. 모델 환경 변수 `FA_CLAUDE_MODEL`의 기본값은 `haiku`이다.
- `kr_formula.py`의 허용 변수는 `mom`, `pair`, `report`. 허용 연산은 `+ - * / **`, 비교 `> < >= <=`, 함수 `abs min max clip tanh sign pos where rank_z`. 임의 Python 표현식, 명령 실행, 잘못된 차원, 비유한 수치, 상수/복잡도 초과를 거부한다.
- `kr_formula_diag.py`는 표본 순위 신호에 대한 영향 비중, 반영 방향, 기본 수식과의 순위 상관, 상위 10종목 중복, 상위 10종목 유지율을 계산한다. **백테스트 수익률을 보고 수식을 튜닝하지 않는다.**
- `kr_formula_agent.propose`는 검사 실패나 성향 불일치를 이전 시도와 함께 다음 요청으로 보내고 **최대 3회** 시도한다. 검사 통과한 후보 중 성향 문제점이 가장 적은 수식을 제시한다. 성향 문제점이 남았다면 경고를 보여준다. 유효 후보가 없거나 LLM이 실패하면 `fallback_formula`로 대체한다. **형식상 유효한 제안이 곧 성향 100% 일치를 뜻하지 않는다.**
- 사용자는 제안된 수식을 수정하거나 그대로 선택할 수 있고, `diagnose` 검사를 통과해야만 세션의 `kr_formula`에 저장된다. 수식 변경 시 기존 포트폴리오 화면의 오래된 계산 결과는 무효화하며, ①·②에서 새 수식을 사용한다.

### 4.3 역할 분리

| 주체 | 책임 | 넘지 말아야 할 경계 |
|---|---|---|
| 수식 제안 에이전트 (Claude) | 성향·요청을 읽고 수식과 쉬운 설명 제안 | Python 코드 실행, 최종 비중 지정, 수익 보장 |
| 수식 파서·진단기 (결정적 코드) | 문법·안전·표본 순위 영향 검증, 최종 적용 허용 | AI의 근거 없는 주장을 사실로 인정 |
| PAIR/REPORT·포트폴리오 엔진 (코드) | 신호 계산, 경로 추론, 위험 기반 최적화·백테스트 | 미래 시점 자료 사용 |
| 수집 에이전트 | 보고서 원문을 구조화하고 근거 기록 | 출처 없는 사실 생성 |
| 설명 에이전트 | 계산 사실과 리포트를 기반으로 5개 항목 설명 | 최적화 비중 변경 |
| 독립 검증 에이전트/규칙 | 주장별 출처 및 숫자 검증, 게시 차단 | 미검증 설명의 PASS 오표기 |

| **AC-04a** | 기준 시점과 누락 REPORT의 중립 처리를 지키며 계산 | `test_kr_report_engine.py`에 시점·누락 회귀 시험 |

**실제 LLM 정확도 측정 범위 밖:** P30(출처 없는 주장 30건 중 27건 이상 거부), M30(왜곡 30건 중 24건 이상 거부), G30(정상 30건 중 27건 이상 유지)은 **정의된 시험 목표**다. 현재 자동 평가의 **모의 검증기 36건 결과로 실제 모델 성능을 인증하지 않는다**. 사람 검토 정답과 실제 CLI 측정 결과가 없는 상태에서는 실측 통과를 표시하지 않는다.

## 6. 결정적 검증·Evals 제출 증거

- 골든 케이스: [`tests/harness/golden_cases.yaml`](../tests/harness/golden_cases.yaml) 26건(설명 12 + 수식 14), 하니스는 [`test_verification_golden.py`](../tests/test_verification_golden.py)와 [`test_formula_golden.py`](../tests/test_formula_golden.py)이다. 정상·경계·금지 입력에 AC를 연결한다.
- 오답 주입: `tests/test_evals_runner_mutation.py` 및 골든 하니스의 결함 주입 테스트. 정답을 바꾸지 않고 실패 검출 여부 확인.
- Evals: [설계](../evals/EVAL_DESIGN.md), 설명 [36건](../evals/evalset.jsonl)·[러너](../evals/run_evals.py), 수식 [24건](../evals/formula_evalset.jsonl)·[러너](../evals/run_formula_evals.py), [결과 JSON·이력](../evals/results/).
- 수식 제안 회귀: `src/diffusion/test_kr_formula.py`, `src/diffusion/test_kr_formula_agent.py`. 가짜 LLM 응답으로 안전성·수정 요청·규칙 기반 대체 동작을 자동 검사하며 실서비스 모델 품질 측정과 구분한다.
- 자동 재현: `.github/workflows/evals-ci.yml` GitHub Actions. 실제 CI 성공 여부는 해당 실행의 로그와 커밋 기준으로 기록한다.
- E2E 사용자 동선: `README.md`와 `docs/FINAL_SUBMISSION.md`. 로컬 Claude 로그인, 시세·체크포인트·수집 상태가 달라질 수 있으므로 GUI 완료 및 품질을 자동 테스트 통과만으로 단정하지 않는다.

## 8. 비기능·운영·범위 고지

- Windows 11/macOS의 로컬 Python 3.11·Streamlit 기반 서비스로, 웹 실행에 GPU/Node/Jupyter는 필수가 아니다. 실제 설치 방법은 `README.md`를 따른다.
- 시세·리포트 수집, 모델 파일, 로컬 CLI·계정 사용량은 환경 의존 요소다. 실패나 미검증 결과는 숨기지 않고 기록한다.
- 고정 44종목·리포트 보유 범위에 따른 생존편향, 리포트 장기 목표가와 20거래일 시계열의 불일치, 세금·슬리피지 등 모델링 한계가 있다.
- 수식 제안은 **사용자의 선호를 계산 가능한 순위 규칙으로 바꾸는 보조 기능**이며 개인별 투자 적합성 심사나 수익 보증이 아니다.
- 근거 및 설문 인용은 `docs/PROBLEM.md` 및 `docs/ontology.yaml`의 `SUR`/`LOG` 출처를 따른다.
