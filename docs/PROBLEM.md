# 문제 정의서 — 개미구조대 최종 MVP (2026-11-17)

> **정본:** [SPEC.md](SPEC.md) v4.0 · [README.md](../README.md) · [docs/ontology.yaml](ontology.yaml). 이전 연구 가설과 사용자 관찰의 근거 ID(SUR/LOG)는 유지한다.

## 1. 사용자 문제

**개인투자자, 특히 금융 수식에 익숙하지 않은 사람은 주가 흐름(MOM), 확산모델의 신호(PAIR), 증권사 전망(REPORT)을 서로 어떻게 신뢰하고 결합해야 할지 결정하기 어렵다.** 또한 결과로 나온 포트폴리오의 종목 순위·비중이 왜 달라졌는지 확인하는 과정에도 부담이 있다.

설문은 2026년 9월 16~30일 10명에게 실시했다. [SUR-01, SUR-02, SUR-11, LOG-001] 일부 응답자의 교차 확인 및 투자 의견 처리 난이도를 관찰했으나, **초보자 전체의 선호 또는 본 MVP의 효과를 통계적으로 입증한 조사로 해석하지 않는다.**

## 2. 최종 사용자 가치

사용자는 수학식이나 Python을 몰라도 네 가지 성향 질문과 선택적 추가 메모로 **AI 에이전트가 추천하는 순위 신호 결합 수식**을 받아볼 수 있다. 수식의 허용 연산·수치·표본 신호 영향은 프로그램이 검사하고, 사용자에게 제안 이유와 진단·경고를 보여준다.

사용자가 수식을 승인하면 **한국 44종목·20거래일·20슬리브**의 로컬 포트폴리오 계산 및 백테스트에 반영한다. 각 종목의 순위 변화, 신규 슬리브 투자 비중, 리포트 근거, 위험 시나리오와 선택적 AI 설명/독립 검증을 함께 확인한다.

**원칙:** 에이전트는 수식과 설명을 제안하지만 투자 비중은 기존 위험 최적화 코드가 계산한다. 이 서비스는 실주문 또는 개인별 투자자문을 실행하지 않으며, 예측·목표가·백테스트 수익을 보장하지 않는다.

## 3. 대상 사용자와 도메인 근거

- R3: 타인의 의견에 완전히 동의하지 못하고 추가 뉴스·시황을 확인했다. [SUR-01, SUR-02]
- R9: 의심 정보를 출처와 교차 검증했다. [SUR-11]
- R7: 의심 정보를 공시로 짧은 시간에 확인한 반례다. 모든 투자자가 판단을 어려워한다고 주장하지 않는다. [SUR-10]
- R6: 번거로워 거래하지 않은 사례는 판단 근거 결핍의 직접 증거로 오인하지 않는다. [LOG-002]

**제품 가설:** 성향·추가 요청을 구조화된 수식으로 제안하고 계산 근거를 함께 제시하면 정보 결합 기준을 스스로 정하기 쉬울 수 있다. 이는 정식 사용자 효용 시험으로 입증해야 할 가설이다. 투자성과 개선과 별개의 평가 축이다.

## 4. 해결 기능 — 최종 구현 범위

| 기능 | 수행 |
|---|---|
| ④ 수식 제안 | 4문항 성향·추가 메모 → Claude 제안 → 문법·신호 진단 → 문제점 피드백·최대 3회 수정 → 규칙 기반 대체 가능 → 사용자 확정 |
| ② 포트폴리오 | 확정된 수식으로 MOM/PAIR/REPORT 결합 순위 계산, 기존 위험 최적화로 신규 1개 슬리브의 목표 비중 산출, 근거·시나리오 표시 |
| ① 백테스트 | 결합 수식에 따른 기간별 NAV, Sharpe, MDD, 변동성, 거래비용 및 날짜별 CSV 제공 |
| ③ 리포트 수집 | 선택적으로 PDF 수집·LLM 구조화·검증, 완료된 보고서를 컨센서스에 반영 |
| 설명·검증 | 계산된 포트폴리오의 5개 영역 설명, AI 독립 검증 실패 시 로컬 설명/미검증 상태 분리 |

## 5. 제품 품질과 검증 가설을 구분

- **재현 가능한 구현/안전성:** 화이트리스트 수식, 오류 피드백, 무단 코드 실행 방지, 리포트 시점 정렬, 검증되지 않은 AI 설명 게시 차단 등은 코드 테스트로 검증한다.
- **AI 성능:** 성향에 얼마나 잘 부합하는 제안을 내는지, 출처 없는 주장을 얼마나 잘 거부하는지 등은 실제 Claude/Codex의 정답 라벨 평가가 따로 필요하다.
- **투자 성과:** 누적수익·Sharpe·MDD 우월성은 구현 사실이 아니라 특정 기간·조건을 정한 별도 실험 결과로만 주장할 수 있다.
- **사용성:** 초보자의 이해도·의사결정 편의 개선은 실제 사람을 대상으로 확인해야 한다.

현재 제출된 `evals/evalset.jsonl` 36건과 골든 12건은 **설명 형식·게시 게이트의 오프라인 회귀 평가**이며 실제 LLM 정확도 실측으로 대체하지 않는다.

## 6. 수용과 제출 기준

제품 범위와 AC는 [SPEC.md](SPEC.md) §5, 사용자 단계·설치와 기대 결과는 [README.md](../README.md), 교수 제출 근거는 [docs/FINAL_SUBMISSION.md](FINAL_SUBMISSION.md) 및 [evals/EVAL_DESIGN.md](../evals/EVAL_DESIGN.md)에 있다.

**최종 범위:** 이미 구현된 네 화면, Claude 기반 성향 수식 제안/검사/적용, REPORT 수집, 포트폴리오·백테스트·설명·검증. 별도의 기획 로드맵을 제출 범위에 포함하지 않는다.

## 7. 반증 조건·성공 정의 (후속 사용자 검증용 제안, 팀 승인 전)

**문제 가설 반증:** 초보 투자자를 대상으로 한 실제 인터뷰에서 금융 정보 결합 기준을 정하는 데 어려움을 겪은 구체적 과거 사례를 충분히 확인할 수 없다면 대상·문제를 재정의한다. 이 문서의 기존 10명 설문만으로 전체 초보 투자자의 어려움이 검증됐다고 간주하지 않는다.

**해결 가설 반증:** 사용자에게 ④ 성향 선택과 수식 제안 기능을 주어도 제안 이유·수식 영향 설명을 이해하지 못하거나 ②·①에 적용하지 못하는 사례가 반복되면 ‘초보자 이용성 향상’이라는 제품 주장을 기각하거나 수정한다.

**성공 지표 후보(미측정):** 도움 없이 ④ 성향 문항 완료율, 제안 수식 확정률, 수식 적용 후 자신의 REPORT 영향 증가·감소를 설명한 사용자 비율, 핵심 동선 완료 시간. 표본 수·합격선은 사람 담당자가 시험 전에 승인해야 하며 측정 전 수치를 실제 관측값으로 기록하지 않는다.
