# 문제 정의서

> 버전: v1 (2026-09-30) · 상위 문서: `ontology-v1.md` (근거 태그 SUR/ASM은 해당 문서의 색인을 따른다)
> 하위 문서: `spec-v1.md`

## 1. 문제 진술 (한 문장)

**2030 개인투자자는 포트폴리오·자산배분 제안을 받아도 그 제안이 현재 시장 상황과 어떤 근거로 연결되는지 확인할 수단이 없어, 제안을 실행하지 못하거나(조언 수신자 4명 중 3명 [SUR-01]), 검증을 포기하고 근거 없이 실행하며(10명 중 6명 "그냥 샀다" [SUR-03, ASM-01]), 스스로 검증을 시도할 경우 수 시간에서 며칠을 쓰고도 확신에 도달하지 못한다 [SUR-02].**

## 2. 대상 사용자 (Who)

- 1차: 투자 행위는 하지만 정보 탐색·검증 루틴이 없는(6/10 [SUR-09]) 2030 저관여 개인투자자
- 특성: 공식 출처(리포트·공시)보다 유튜브·커뮤니티에 의존 [SUR-04], 이미 4/10이 생성형 AI에게 금융 판단을 묻기 시작 [SUR-06]
- 제외: 자체 백테스트·모델링이 가능한 전문가급 투자자 (설문 R1 유형) — 스스로 검증 수단을 보유

## 3. 발생 맥락 (When / Where)

1. 자산배분·종목 제안을 받은 직후, 실행 여부를 판단해야 하는 시점 [SUR-01]
2. 시장 급변(급락·급등) 시 "지금 이게 맞는 건가"를 확인하고 싶은 시점 (설문 Q6: 호르무즈발 폭락 매도 후 반등 사례)
3. 접한 정보가 사실인지·최신인지 의심되는 시점 — 현재는 "그냥 믿음"이 다수 대응 (설문 Q11)

## 4. 현재 대안과 한계

| 대안 | 한계 | 근거 |
|---|---|---|
| 금융앱·로보어드바이저 추천 | 비중만 제시, 근거 설명 부재 → "거짓같아서" 그대로 실행 0/10 | SUR-07 |
| 유튜브·커뮤니티 | 접근성은 높으나 출처·최신성 보증 없음, 낡은 정보로 실손실 사례 | SUR-04, SUR-05 |
| 지인 | 의견 불일치 시 판단 불가 ("모두 동의할 수 없어서") | SUR-01 |
| 직접 교차확인 | 2시간~며칠 소요, 확신 획득 실패 사례 존재 | SUR-02 |
| 범용 생성형 AI (GPT 등) | 이미 사용 중이나 답변의 출처·시점·사실성 검증 계층 없음 | SUR-06, ASM-03 |

공통 한계: 어떤 대안도 **"이 비중·제안이 지금의 시장 정보와 어떻게 연결되는가"를 출처와 함께 추적 가능한 형태로 제공하지 않는다.**

## 5. 손실 (측정 가능한 결과)

- 실행 보류로 인한 의사결정 정지 — 조언 수신자의 3/4 [SUR-01]
- 검증 시간 비용 — 건당 2시간~며칠, 확신 도달 실패 포함 [SUR-02]
- 오정보 기반 판단의 금전 손실 — 실사례 1건 확보 (낡은 법안 정보 기반 파생 포지션) [SUR-05]

## 6. 문제가 아닌 것 (Non-problems / 조사로 기각·축소된 가설)

- **금융정책·공공지원 탐색의 헛걸음·중도포기**: 설문에서 0/10으로 확인되지 않아 프로젝트 스코프에서 제외했다 (설문 Q19, Q24)
- **유료 지불 의사**: 전 도메인 0/10 [SUR-08] — 수익모델은 본 프로젝트의 문제가 아니며, 무료 사용을 전제한다 [ASM-05]

## 7. 미검증 가정 (인터뷰 검증 백로그)

본 문제 진술은 다음 가정 위에 있으며, 인터뷰 단계에서 검증한다. 상세는 `ontology-v1.md` §0 ASM 색인.

- ASM-01: "그냥 샀다"는 학습된 검증 포기다 (기각 시 대상 사용자를 "미실행" 유형으로 좁힌다)
- ASM-02: 출처 연결 설명이 실행 확신을 높인다
- ASM-03: 생성형 AI 사용자는 검증 계층을 원한다

## 8. 해결 방향 (스펙으로의 연결 — 설계는 spec-v1.md)

문제의 세 축이 스펙의 세 요구사항 축으로 1:1 대응된다:
근거성 부재(PAIN-01) → 설명 생성(FR-03) / 최신성 불확실(PAIN-04) → 실시간 수집(FR-02) / 사실성 검증 불가(PAIN-05) → 검증 에이전트(FR-04).
